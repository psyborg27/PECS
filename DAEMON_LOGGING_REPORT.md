## Gaps and risks

- `.pecs/daemon.log` is empty, so daemon activity is not currently recorded in the expected log file
- The wrapper uses `setsid` / `nohup` output redirection, but no line buffering or rotation
- The runtime health artifact is authoritative for current workspace state; logs are secondary
- There is no explicit file retention policy or archived logs in `.pecs/`

## Recommended logging fixes

- Persist daemon stdout/stderr into `.pecs/daemon.log` with write flushing
- Add a log rotation policy or size limit for `.pecs/daemon.log`
- Add VS Code task output integration or a dedicated `PECS: Show Daemon Log` task
- Improve daemon status commands to expose recent log lines when health degrades
