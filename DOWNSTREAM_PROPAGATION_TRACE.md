# DOWNSTREAM_PROPAGATION_TRACE

## Summary

The daemon is correctly running and updating the refresh lifecycle artifacts (`daemon_cycle_validation.json`, `daemon_health.json`, `daemon_state.json`, `continuity_refresh_state.json`).

The remaining stale artifacts are:
- `.pecs/ai_chat_history.json`
- `.pecs/compact_bundle.json`
- `.pecs/active_context.json`
- `.pecs/topology_compact.json`

These are generated by the runtime-local daemon and must be regenerated before bridge export. The current propagation gap is not in the bridge itself; it is in the upstream runtime extraction/rebuild chain and in the chat history ingestion path.

## Actual trigger chain

### ai_chat_history.json

Should refresh on:
- external chat append operations via `.pecs/tools/append_ai_chat_history.py`
- daemon startup system event (`daemon_started` appended by `WorkspaceContinuityDaemon._append_system_chat_event`)

Currently refreshes via:
- `WorkspaceContinuityDaemon._poll_chat_history()` comparing file mtime
- on detected update, `WorkspaceContinuityDaemon._on_chat_history_update()` → `_on_chat_history_update_unlocked()`

Notes:
- the daemon watches the same path: `self._chat_history_path = workspace_root / ".pecs" / "ai_chat_history.json"`
- if external integration does not write to this path or uses a different path, the daemon never sees the event

### compact_bundle.json

Should refresh on:
- topology rebuild (`WorkspaceContinuityDaemon._rebuild_runtime_topology()`)
- ai chat history update (`_on_chat_history_update_unlocked()`)
- runtime activation update (`_on_activation_update()`)

Currently refreshes via:
- `WorkspaceContinuityDaemon._build_compact_bundle()` called from each of the above code paths
- written to `.pecs/compact_bundle.json` in `_rebuild_runtime_topology()` and `_on_activation_update()`
- also written to cleanup/update on chat updates when `runtime_locality_payload` is present

### active_context.json

Should refresh on the same events as `compact_bundle.json`.

Currently refreshes via:
- `WorkspaceContinuityDaemon._build_active_context_payload()` called from:
  - `_rebuild_runtime_topology()`
  - `_on_chat_history_update_unlocked()`
  - `_on_activation_update()`

### topology_compact.json

Should refresh on:
- any topology rebuild triggered by `.py` changes
- startup full scan when `compact_bundle.json` or `locality_index.json` are missing/empty

Currently refreshes via:
- `WorkspaceContinuityDaemon._rebuild_runtime_topology()`
- writes `topology_compact.json` with the current `self.runtime_topology_edges`

## Key code references

- Topology rebuild and core artifact write: `runtime/daemon/workspace_continuity_daemon.py:_rebuild_runtime_topology()`
- Chat history refresh cycle: `runtime/daemon/workspace_continuity_daemon.py:_on_chat_history_update_unlocked()`
- Runtime activation update: `runtime/daemon/workspace_continuity_daemon.py:_on_activation_update()`
- Bridge refresh wrapper: `runtime/daemon/workspace_continuity_daemon.py:_execute_bridge_refresh()`
- Bridge export path: `.pecs/bridge/export_workspace_continuity.py`

## Observed propagation behavior

- A bridge refresh can succeed and update `continuity_refresh_state.json` even when core runtime artifacts are stale.
- The bridge export path does not regenerate `topology_compact.json`, `compact_bundle.json`, or `active_context.json`; it only reads them and writes continuity exports.
- Therefore a successful `bridge refresh` is necessary but not sufficient to guarantee fresh core runtime projection artifacts.

## Implication

The remaining gap is upstream: the daemon must ensure core runtime artifacts are rebuilt and/or the chat history ingestion path must be reliably populated before the bridge export can produce fresh runtime locality outputs.
