# PECS FAQ

## What is PECS?

PECS is an experimental Alpha 1 system for deterministic runtime continuity in developer workspaces. It builds runtime topology, execution locality, and evidence structures to support AI-assisted code reasoning.

## Why was PECS created?

PECS was created to provide a continuity layer that helps AI tools understand which files are execution-adjacent, which modules own runtime behavior, and which workspace elements should be considered together.

## How is PECS different?

PECS is different because it relies on structural runtime evidence rather than semantic embeddings. It focuses on runtime topology, entrypoints, ownership, and deterministic artifact generation.

## Does PECS use AI?

PECS itself does not perform AI reasoning. It produces artifacts and projections used by AI consumer adapters. The consumer adapters can then feed context to AI tools.

## What is PECS-LITE?

PECS-LITE is the stateless projection layer. It reads PECS-PRO artifacts and returns bounded, consumer-shaped projections. It does not own workspace continuity state.

## What is PECS-PRO?

PECS-PRO is the continuity authority. It owns runtime topology reconstruction, workspace graph and registry construction, evidence correlation, and `.pecs/` artifact generation.

## How does querying work?

A query is handled by `pecs query-pipeline`. The process is:

1. normalize query terms
2. correlate terms against workspace evidence
3. select evidence clusters
4. build a navigation graph
5. emit deterministic JSON

## How are artifacts generated?

Artifacts are generated by the daemon refresh cycle and written under `.pecs/` in the workspace. The daemon scans source files, resolves imports and entrypoints, builds the workspace graph, and emits continuity payloads.

## How do I upgrade?

Use `pecs upgrade-workspace <workspace_root> --repo-root <repo_root>`. It runs the canonical upgrade pipeline, refreshes assets, regenerates continuity state, and validates the workspace.

## How do I refresh?

Use `pecs refresh <workspace_root>` to rebuild continuity artifacts from the current workspace state.

## How do I validate?

Use `pecs validate <workspace_root>` to validate continuity outputs. Use `pecs doctor` to diagnose install and environment issues.

## Can I edit `.pecs/`?

No. `.pecs/` files are generated infrastructure only. Live workspace source files are the authoritative code.

## How do I troubleshoot?

Common commands:

- `pecs doctor`
- `pecs status <workspace_root>`
- `pecs health <workspace_root>`
- `pecs refresh <workspace_root>`
- `pecs validate <workspace_root>`

Inspect `.pecs/logs/` for daemon and continuity errors.

## What does Alpha 1 mean?

Alpha 1 means the software is experimental and implementation-focused. It is not complete, and the current documentation describes only the behavior that exists now.
