# Consistency Audit — Documentation vs. Implementation

Compares documented behavior against actual implementation code. Discrepancies are either documentation errors or implementation drift.

---

## Discrepancy 1: `--dump-workspace-graph` / `--dump-workspace-registry` Flags

**Severity: High**

**Documented in:**
- `docs/architecture.md` — "Optional dumps are controlled by daemon flags `--dump-workspace-graph` and `--dump-workspace-registry`."
- `docs/artifacts.md` — Lists optional dumps under same flags.

**Implementation check:** `grep -n "dump-graph\|dump-registry\|dump-workspace" runtime/daemon/workspace_continuity_daemon.py` returns **no results**.

These flags do not exist in the current daemon implementation. The workspace graph and registry dumps are controlled differently (possibly via `PECSQueryPipeline` with `--use-dumps`, or generated by a different mechanism).

**Action:** Update `docs/architecture.md` and `docs/artifacts.md` to remove references to these CLI flags, or document the actual mechanism for enabling dumps.

## Discrepancy 3: Daemon Flags Not Matching Documentation

**Severity: Medium**

**Documentation** (`docs/architecture.md`): Claims the daemon controls optional serialization via `--dump-workspace-graph` and `--dump-workspace-registry`.

**Implementation** (`workspace_bridge_cli.py`): The `query-pipeline` command has `--use-dumps` (prefer daemon-written files) but the daemon itself doesn't produce these files via flags.

The daemon does write `workspace_registry.json` in the PECS repo's own `.pecs/` (it exists at 753 lines), but this appears to be a side effect of the refresh cycle, not a flag-controlled behavior.

## Discrepancy 4: Engine Architecture Document vs. Implementation

**Severity: Medium**

**Documented:** `PECS_AUTHORITY_ENGINE_ARCHITECTURE.md` (13.5 KB) describes an "authority engine architecture" with a complex authority fusion pipeline.

**Implementation:** The actual authority model is straightforward — PECS-PRO is the sole authority; PECS-LITE is a stateless adapter. There is no "authority engine" class, no authority fusion pipeline, and no authority engine module anywhere in the code.

**Action:** This document should be archived as an obsolete design proposal.

## Discrepancy 5: File/Class/Function Resolution Design vs. Implementation

**Severity: Medium**

**Documented:** `PECS_FILE_CLASS_FUNCTION_RESOLUTION_DESIGN.md` (10.9 KB) describes a resolution system with specific design choices.

**Implementation:** The actual implementation is `navigation_builder/line_range_resolver.py` (a `LineRangeResolver` that parses files with `ast`). This is functionally different from what the design document describes.

**Action:** Archive the design document. Update if needed to describe the actual implementation.

## Discrepancy 6: PECS Object ID Producer Design vs. Implementation

**Severity: Medium**

**Documented:** `PECS_OBJECT_ID_PRODUCER_DESIGN.md` (9.8 KB) describes a standalone PECS_ID generation system.

**Implementation:** PECS_ID generation is embedded in the runtime workspace scanner (`runtime/workspace/import_locality_mapper.py` and related modules), not a standalone producer module.

## Discrepancy 8: Missing Schema on Generated Artifacts

**Severity: Low (documentation doesn't claim schema fields exist)**

**Documented:** `docs/query-pipeline.md` claims the pipeline emits JSON with schema `pecs.query_pipeline.v1`. The `PECS_QUERY_CONTRACT.md` defines response fields.

**Implementation check:** The following generated files at `.pecs/` have **no** `schema` field:
- `active_context.json`
- `daemon_health.json` (has `daemon_version` but no `schema`)
- `daemon_state.json`
- `workspace_registry.json`
- `continuity/active_topology.json`

Only `continuity_bridge.json` has `"schema": "pecs.bridge.config.v1"` and `workspace_assets_manifest.json` has `"schema": "pecs.workspace_assets_manifest.v1"`.

**Action:** No documentation change needed — but adding schema fields to generated artifacts would improve cross-version migration detection. This is a code change outside scope of this work package.
