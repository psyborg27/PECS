# Engineering Protocol

## PRIMARY OBJECTIVE

CONTINUITY STABILIZATION

NOT:

ARCHITECTURAL REWRITING

---

# CORE OPERATING PRINCIPLE

LIVE WORKSPACE STRUCTURE ALWAYS HAS HIGHEST AUTHORITY.

DO NOT:

- trust historical AI memory blindly
- trust stale backups blindly
- trust abandoned implementations blindly
- infer canonical ownership from filenames alone

Canonical ownership must be inferred from:

- live imports
- runtime wiring
- active symbol references
- actual dependency chains
- currently active execution paths

---

# SAFE DEVELOPMENT MODE

ALL changes must follow:

MINIMAL MUTATION PRINCIPLE

Meaning:

- smallest safe change
- smallest safe fix
- smallest safe reconciliation
- preserve existing runtime behavior

DO NOT:

- redesign architecture
- create replacement frameworks
- introduce speculative abstractions
- create new wrapper layers
- perform broad rewrites
- move major ownership boundaries

---

# MOST IMPORTANT RULE

Treat this workspace as:

A CONTINUITY-STABILIZATION PROBLEM

NOT:

A GREENFIELD SOFTWARE PROJECT

Preserving working runtime behavior is more important than architectural elegance.
